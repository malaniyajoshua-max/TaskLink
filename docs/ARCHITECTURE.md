# 架构与维护

## 进程边界

React 界面通过 shared/contract.ts 中定义的命令调用 preload。主进程验证来源和输入，再将数据操作交给 worker。界面没有 Node、数据库、文件路径或登录令牌访问权限；聊天窗口只开放聊天所需命令。

数据工作线程持有当前账号的 LocalStore、同步引擎和附件传输器。退出账号后销毁这些对象，切换账号会重新打开对应数据库。TanStack Query 管理界面查询缓存；Zustand 保存页面导航状态，两者都不负责持久化任务。

## 本地写入与同步

LocalStore.saveInner 在同一个事务内写入任务快照和 Outbox 操作。事务期间的缓存变更先写入暂存表，COMMIT 后再发布到内存缓存；ROLLBACK 不暴露中间状态。批量修改和复制子任务复用这条路径，因此保持相同的权限、引用和日期检查。

同步请求使用独立 operation_id。请求发出后，队列中的已准备负载保持不变；用户后续编辑产生新操作，避免重试同一 ID 时发送不同内容。网络错误保留队列并退避重试。版本冲突由用户选择解决方式，服务端负责最终的工作区权限检查。

状态按钮使用 tasks.status 命令。读取最新记录、检查可选 expectedStatus、保存状态及父子联动在仓储事务内完成。tasks.undoStatus 只携带本机撤销记录 ID，仓储检查父子成员与状态后恢复各自旧状态，不发送旧的整条任务快照，避免把新描述或其他同步字段覆盖回去。

## 日期与继承

接口日期使用带时区的 ISO 时间，视图按本机日历日计算边界。今日视图包含未完成的逾期任务，以及今天到期的已完成任务。未来视图覆盖今天及之后七天，区间右端不包含在内。

一级子任务可以继承父任务的截止时间、提醒和优先级。显式批量设置某个属性时会关闭该属性继承。单独复制子任务时，先取出当前生效的截止时间与优先级，再解除父子关系。

## 专注计时

shared/focus.ts 是不访问时钟或数据库的状态机，时间由调用方传入。运行中的计时保存 endsAt，暂停时保存剩余秒数。界面每秒刷新只是显示逻辑，系统休眠、窗口节流或进程退出不会延长截止时刻。

只有 running 到 completed 的转换会增加累计记录。worker 在读取或操作计时器时先结算并保存，重复读取不会重复计数。计时与任务状态互相独立，完成一段专注不会完成关联任务。

## 设置与界面状态

settings.patch 只更新调用方提供的字段。补丁 schema 不带默认值，避免切换主题时把看板偏好或通知设置重置。布局、排序、主题与专注记录按账号保存在本机；导航状态和临时筛选在界面中管理。

shared/themes.ts 集中定义主题 ID、显示名称、语义色与日夜模式。主界面和聊天窗口共用 src/use-theme.ts：data-theme 继续表示 light/dark，data-season 与 data-appearance 表示季节及完整主题 ID，语义颜色写到根元素 CSS 变量。切换经典主题或卸载账号界面时清理这些变量，避免前一账号的季节颜色留在后续界面。src/themes.css 负责季节装饰、主题预览和主按钮文字颜色；预览使用独立的 --preview-* 变量，不影响页面本身。

原生 dialog 在 showModal 后设置初始焦点。快速录入在输入框解除 disabled 后恢复焦点。修改这些时序时，应运行 workspace 和 productivity 桌面测试，覆盖中文组合输入、快捷键和连续创建。

测试数据、日志和快照应放在 work 或外部临时目录。测试脚本只结束自己创建的进程，失败时保留现场。包内程序通过 renderer CDP 验证，正常启动不开放调试端口。

生成的 OpenAPI 类型应通过 scripts/contracts.ps1 更新，不手工改生成文件。修改持久化格式前，需要同时考虑已有账号数据库、加密备份、Outbox 重试和服务端兼容性。
